需求確認日期：2026-10-24。本文保存穩定需求、架構與驗證門檻；實際完成狀態、使用者驗收與下一步只記於根目錄「專案進度.md」，不要以本文另建第二份交接。

後續範圍調整：使用者已要求先公開目前完成的工作流與三組展示，較完整／專業流程等日後有需要再做。因此下方階段是保留的設計研究，不再作為本次發布的阻擋條件；本次實際發布依公開清單與專案進度，不順便安裝新模型或製作長片。

## 目標與執行位置

工作流應讓另一台電腦的Agent在取得程式、閱讀Markdown、檢測硬體及取得必要私人素材後，能引導使用者完成教學／宣導影片。使用者可提供角色、台詞及教學圖片，也可讓Agent協助擬稿與製圖；既有已確認選擇沿用，缺項才詢問。

公開層規劃為GitHub程式、文件與GitHub Pages說明／展示頁；生成與合成在使用者電腦執行。[GitHub官方](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)定義Pages為靜態網站服務，因此Python、TTS、SadTalker與本機GPU不會因發布HTML而在Pages伺服器執行。如果日後要在網頁按鍵啟動本機工作流，須另設本機服務或桌面程式，這不在第一版發布必要範圍。

第一版Pages用途：解釋輸入選項與操作步驟、展示已允許公開的三模式、下載範例需求設定、連到版本化README及MD。公開示範目前僅有已指定的阿忠／萌萌1202窄範圍例外；接受阿德影片不等於授權公開本人照片、聲音、影片或可編輯身體圖集。

## 輸入分流與身體規則

此決定取代早期「一律優先推薦阿忠固定身體」的預設。

| 使用者提供的內容 | 預設處理 | 需確認或補充的資料 |
| --- | --- | --- |
| 現成完整卡通／Q版角色 | 保留該角色及身體；畫風已適用時直接使用 | 角色、主題、台詞來源、三模式、位置／大小；遮擋處是否需補繪 |
| 真人全身照 | 以本人身形、服裝及鞋為參考轉Q版，保留可辨識特徵 | 使用者指定畫風，或由選單選定；頭身比例與成品靜態預覽 |
| 真人半身／大頭照，要求全身影片 | 優先找使用者已標示為同人的全身參考 | 沒有全身參考時先請使用者提供，或確認下半身服裝／鞋／姿勢後補繪，不能宣稱還原不可見部位 |
| 明確指定另一個卡通人物身體 | 以使用者提供的身體為基準，新頭像配合其線條、色彩、材質與比例 | 身體來源、頭像人物及構圖；不能因某張頭像已驗收就省略新頸部／膚色接合檢查 |
| 只有頭像用途 | 只製作或沿用頭像 | 不自行延伸全身或套用制服 |

卡通人物名稱依使用者命名，身體素材另有穩定ID與來源檔，不因口語稱呼不同就替換素材。若指定身體只提供一張平面圖而沒有分層，準備關節素材仍是必要工作，不能承諾貼上一個頭即完成三模式。

真人圖優先使用使用者指定的GPT Image 2.5。依[OpenAI官方文件](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst)，精細編輯可選Sunburst；Agent實際可用工具及帳號權限仍須另查。若工具不暴露精確後端，只記錄「內建image_gen、確切模型未暴露」，不能回頭將舊素材寫成已驗證某個API型號。無該能力時，提出本機千問方案或沿用已接受圖片，品質驗收方式相同；不偷偷切換供應商。

## 標準製作順序

1. **需求與來源**：確認角色輸入、主題／對象、預期長度、台詞由誰提供、背景由誰提供、風格、身體、動作模式、位置／大小。既有授權不重問。需求以專案相對路徑保存，原始素材不覆寫。
2. **角色靜態**：保留人物特徵，檢查臉型、髮型、眼鏡等辨識特徵、服裝、鞋、頭身比例與頸部。先接受主設計，再延伸視角與可動部位；不是每支新台詞都重畫角色。
3. **講稿與背景分鏡**：使用者給台詞則先校稿，未提供則依主題／年級／宣導重點擬稿供確認。背景可用使用者圖片、授權素材或生成插圖，記來源；教學文字與字幕使用本機繁體字型排版，避免仰賴生圖直接畫出完整繁體文字。不可固定只有三個硬編碼教材面板。
4. **本機語音試聽**：依speech-policy、硬體與合法可用參考聲，先做短句。成人男／女與男童感／女童感是需求組別，不是已安裝的聲線；台灣口音先試，沒有通過才明確列普通話備案。音色、咬字、停頓及音量通過後凍結WAV與時長，不自動克隆家豪或萌萌。
5. **嘴型與眼睛短測**：新人物先用原本有嘴巴的Q版頭像，做3～5秒SadTalker試樣，檢查相似度、眼鏡、嘴唇／牙齒及停頓。局部眼皮、穩定ROI均逐角色校準，不能複用阿德座標便聲稱相容。
6. **身體與三模式**：沿用已接受素材；新身體準備重疊肩髖與連續肘膝網格。模式①只有手部、②手腳與頭部自然動作、③較活潑原地動作。三者同一台詞／原音，留在使用者指定活動區；檢查完整抬放過程，不以只有峰值一張當驗證。
7. **正式時間軸**：用已接受音訊對齊字幕與背景切換，新增語音不能套舊字幕／嘴型秒數。嘴型由整段真實音訊驅動，不能循環短嘴型冒充完整講話；長片分段後需校正音訊、眼皮及全片時鐘。
8. **整合交付**：先短片，再逐步延長。交付所選模式MP4、三模式比較預覽、字幕、來源／版本清單及可重建設定；音訊、字幕、頭身、肢體、教材各自可追溯。輸出另存輪次，接受後凍結，修改不覆寫基準。

## 給Agent的文件與設定契約

AGENTS規定行為；README給穩定用途與入口；專案進度是唯一最新狀態；本文件描述通用流程；生圖研究文件列模型、授權與視角素材規格；硬體文件列檢測與保守路由；詳細失敗與驗證仍回寫對應踩坑文件。

通用執行器應讀取一份作品需求設定，至少含：作品ID、輸入類型與檔案、人物／身體來源ID、保留特徵、風格、身體策略、構圖、模式、定稿台詞、TTS模型／聲線或已確認WAV、背景素材及字幕語系、輸出規格、各階段驗收。這是下一階段介面規格，**尚無任意新作品的一鍵runner**。不得把round11專用腳本說成已實作所有分流。

每步應有輸入檢查、輸出清單／SHA256、工具及模型版本、參數、執行耗時與錯誤；耗時步驟可續跑／快取，檔案已存在且來源相同時不得盲目重跑。固定seed僅協助重現，不保證跨GPU位元組一致或人物一定一致。安裝分開隔離環境，對嘴既有Python3.10不可拿來混裝生圖與TTS。

Agent回答能力問題時，分清「文件候選」「安裝完成」「短測可執行」「角色品質已驗收」「換機可重建」，每個判斷都連到實際證據。缺少私人素材、參考聲或工具權限時說明具體缺項，不能把repo下載成功當成製片成功。

## 品質優先與硬體適配

使用者原則：硬體較弱可以慢，不能自動大幅降畫質、換回已拒絕的嘴型、刪除眨眼或省略接合檢查。相同作品先保持已接受的解析度／幀率／角色素材／嘴型後端及動作；全新輸出規格再由使用者選擇。1080p檔案本身不足以證明品質，仍需檢查素材有效細節與最終畫面。

優先調整worker=1、batch=1、CPU／GPU卸載、分段與快取；數值精度、量化、少步數／蒸餾或較小模型可能影響身份與細節，須以同一角色比對，不能當作等品質切換。若品質方案在本機無法合理執行，保留既有已接受資產，或把素材交給使用者另一台較強電腦完成生圖，回本機合成；不自行租雲端或上傳私人圖。

doctor目前有硬體與候選邏輯，但未涵蓋生圖管線、模型子環境探測、實際峰值資源與品質保護；舊的2d-puppet-rhubarb通用推薦不能覆寫阿德已接受的SadTalker。下一階段要將角色／聲音／生圖／對嘴／合成分開判斷，不用單一GPU總容量決定整條路線。

## 發布與私人搬移

repo／Pages放程式、固定依賴、模型來源／授權說明、需求樣板與可公開示範。原始照片、私人語音、角色視角／表情庫、可編輯圖集、LoRA權重與模型本體另保存在使用者授權的私人素材包；安裝目錄、快取及本機絕對路徑不打包。私人包要有來源版本、校準設定、允許清單、SHA256及拒絕覆寫／路徑跳脫的匯入檢查。

公開Pages部署不可直接複製整個專案根目錄，亦不可直接把私人round11預覽頁當公開成品。發布前依白名單建立獨立靜態輸出，只放授權範例、使用指南與agent可讀Markdown。使用者目前描述的是最終目的，本次不建立遠端、不push、不部署；之後按專案進度記錄明確發布要求。
