# 硬體自適應與跨電腦工作流

這份文件規範後續 Agent 如何依當下電腦選方案。實際進度、跑過哪些項目及失敗原因，一律讀取並更新根目錄的 `專案進度.md`。

## 設計與目前範圍

採用「可重跑的 Python／Node 工作流＋之後可加的互動 Skill」。硬體檢測與推薦、配音、嘴型時間、字幕、原地動畫、渲染、素材搬移分開保存。Skill 適合負責問需求、引導驗收及呼叫這些命令；不應把大型模型或私人素材塞進 Skill。

2026-10-24品質優先規則：較慢可以接受，不因硬體弱自動降解析度、換回已拒絕嘴型或刪眨眼／接合檢查。先單worker／batch、卸載、快取及分段；量化／少步數／小模型須同角色驗收。全身輸入預設保留本人／原角色身體，指定才換卡通身體。完整架構見[通用工作流](通用教學影片工作流與公開發布規劃.md)，生圖候選與視角庫見[本機生圖研究](本機生圖與角色多視角資產研究_2026-10-24.md)。這是更新後的Agent規則，doctor的舊分級程式尚未實作完整生圖與品質保護，不假稱已全自動完成。

目前已有阿忠2D分層示範，以及阿德SadTalker頭像＋局部眨眼＋本人服裝連續網格。第十一輪13秒三模式已接受，完整CPU對嘴可重現，但新人物仍須逐角色短測，不能宣稱任意照片一鍵套用。SadTalker有獨立CPU安裝、短測及完整原音入口；大型生圖／GPU影片與本機TTS仍屬選型／待介接，最新驗收範圍看專案進度。

## 每次開始的順序

1. 讀 `AGENTS.md`、`README.md`、`專案進度.md`，再讀專案其餘 Markdown；略過依賴、快取與輸出。
2. 檢查 Git 狀態，保留既有變更。重新跑硬體檢測，不能把其他電腦的報告當成這台的資料。
3. 新作品先詢問：輸入類型、頭像／全身、風格、服裝與用途；全身再選動作模式、位置與大小。既有作品重跑則沿用該版本已確認設定。
4. 依推薦呈現「優先方案、替代候選、未通過原因、尚需實測」，由使用者選擇品質、速度、是否連網及費用取捨。
5. 先做短配音試聽；驗收後才固定正式時間軸。測試版必須註記尚待驗收。
6. 使用同一音訊檢查嘴型、三種模式與活動範圍，再檢查字幕、教材背景及 MP4。只移動整張圖片不能當成分層肢體實測。

## 檢測命令與輸出

```powershell
.\.venv\Scripts\python.exe -m avatar_workflow doctor
.\.venv\Scripts\python.exe -m avatar_workflow doctor --offline
```

唯讀收集 OS、CPU 描述、邏輯核心、總／可用 RAM、磁碟空間、NVIDIA 型號、總／可用 VRAM、驅動與可取得的 compute capability，另列 Python、Node、瀏覽器與 PyTorch 是否存在。報告存 `work/hardware/report.json`，不提交 Git。無法取得的值保留未知，不推定為高規格。舊版 `nvidia-smi` 不支援架構查詢時退回基本查詢。

不把多張 GPU 顯存相加；Apple 統一記憶體不當作 CUDA VRAM；偵測不到 NVIDIA 時，仍可跑輕量流程。PyTorch 存在不代表 CUDA 推論成功，`runtime_verified` 只有在實際模型短測通過後才能升級；目前程式一律回報 false。

SadTalker的選用環境位於 `work/sadtalker/venv`，不在主`.venv`內。doctor目前不自動驗證這個子環境，也不因一次CPU短測就將全域`runtime_verified`設為true；以該試驗的manifest、模型雜湊、實際MP4及使用者品質驗收分開判斷。GT710不使用CUDA，CPU可執行也不代表生成速度適合長片。安裝與原嘴短測入口見README及 [SadTalker本機嘴型實測](SadTalker本機嘴型實測與踩坑_2026-10-24.md)；換成較強筆電仍須重跑doctor、另外確認PyTorch／CUDA／顯卡架構與角色效果，不能直接把CPU鎖定檔換個GPU開關就算完成驗證。

聲音建議現在會讀 `config/speech-policy.json`，新作品標示本機TTS優先及planned狀態；離線模式仍以既有音訊為先。這只是選型建議，不是已安裝或可生成；完整本機TTS介接尚未完成。通用硬體分級仍可能列2D路線，不因此覆寫本專案已選的SadTalker頭像與已接受音檔。

## 推薦規則

以下數字是本專案保守的「進入評估門檻」，不是供應商最低規格，也不保證能裝或跑得動。不同解析度、精度、卸載、注意力套件與模型版本都會改變需求。

| 條件 | 優先方案／下一個評估 | 狀態 |
| --- | --- | --- |
| 無適合 GPU、架構未知或舊 GPU | 保留已接受圖／音，評估CPU SadTalker＋分層／連續網格＋HyperFrames；新的本機TTS另試 | 本PC已有CPU完整對嘴；換機仍須短測。Rhubarb／Edge僅舊範例或明確選用備援，不覆寫已接受嘴型／語音策略 |
| RAM 至少 12 GiB | 可評估 BreezyVoice CPU 台灣華語 | 尚未安裝；需參考音訊與 Windows 依賴整理 |
| 單張 NVIDIA：compute capability ≥ 8.0、驅動主版 ≥ 550、VRAM ≥ 6 GiB、可用 ≥ 4 GiB，RAM ≥ 16 GiB、可用 RAM ≥ 8 GiB、磁碟 ≥ 10 GiB | 加入 Qwen3-TTS 0.6B 候選，影片仍用 2D | 先測 CUDA、口音及速度，不保證原生台灣口音 |
| 上述 GPU 條件且 VRAM ≥ 24 GiB、可用 ≥ 20 GiB、RAM ≥ 32 GiB、可用 RAM ≥ 24 GiB、可用磁碟 ≥ 100 GiB | 下一個評估改為 InfiniteTalk／LongCat Avatar 1.5 的短片比較；保留 2D 基線 | 大型模型候選；LongCat 可能仍需更多 VRAM，不自動安裝 |

可用 RAM 少於 4 GiB 時建議先釋放記憶體並使用單一 worker；磁碟不足 10 GiB 時建議暫緩下載。大型 GPU 目前忙碌時不升級影片模型。未知值採保守回退；不會因 GitHub 星數高就忽略硬體、口音、授權或實測效果。

要調整門檻：編輯 `avatar_workflow/recommend.py`，記錄依據與日期，並更新 `tests/test_workflow.py` 的高／低規格、忙碌 GPU、未知架構、多 GPU、離線與非 CUDA 案例。不要把某一次成功概括為所有同顯存顯卡皆可。

生圖需另偵測完整管線、文字編碼器、VAE與量化／卸載方式，不能只看模型名稱的7B或4B。規劃分開回報硬體候選、子環境相容、模型短測與角色品質；目前report只含有限主環境runtime資料。頁面／repo可以教另一台Agent操作，不能讓其自動取得GPT生圖能力或私人素材；模型在本機執行，Pages只放靜態說明與授權展示。完整新人物私人包尚未擴充，既有舊pack不是round11完整搬移命令。

## Windows 新電腦安裝

準備 Python 3.12、Node.js 22 以上、npm；可選 uv。只在專案內安裝，不修改全域 Python 套件。不要複製舊電腦的 `.venv`、`node_modules`、GPU 驅動或二進位快取。

```powershell
# 在下載／clone 後的專案根目錄執行；如 Python 不在 PATH，可給完整路徑。
.\scripts\setup.ps1 -PythonCommand python -RenderTools
.\.venv\Scripts\python.exe -m avatar_workflow doctor
```

`setup.ps1` 安裝固定 Python／npm 版本；`-RenderTools` 才下載官方 Rhubarb release、FFmpeg 官網所列 Gyan Windows build，以及官方 Chrome for Testing。下載數量約數百 MB，不含大型 AI 權重。FFmpeg 9.0.2 封存與供應者公開 SHA256 比對；Rhubarb 保存自行計算的 SHA256，兩者驗證強度不同。二進位、環境及快取均在忽略範圍。瀏覽器為獨立 headless shell，不使用個人瀏覽器設定檔。

若政策限制 PowerShell 腳本，不自行放寬全機執行原則；依序手動執行腳本內命令即可。若用 uv 建立環境，虛擬環境未必含 pip，使用 `uv pip --python ...` 即可。

Linux／macOS 的硬體偵測有回退，影音流程尚未在這兩個系統實測。先用系統套件管理器提供 FFmpeg 與 FFprobe，再建立 `.venv`、安裝鎖定依賴及 `npm ci --ignore-scripts`；macOS ARM 不可套用目前 Rhubarb x86_64 自動安裝。不要把 Windows 的已驗證狀態搬過去。

## GitHub 與 Google 雲端硬碟的分工

GitHub 保存程式、固定依賴、設定、已允許散布的字型與 OFL 授權、研究及使用說明。原始照片、生成角色、聲音、輸出及模型預設忽略。尚未執行遠端建立、push、雲端上傳或公開發布；之後由使用者指定 repo、可見性與授權範圍。

使用者另指定 `examples/azhong-mmeng-1202/` 作為未來repo展示的例外：保留已驗收的三支MP4、配音WAV、字幕、預覽圖、比較頁、聲音選單與版本雜湊。下載後可直接觀看，不需安裝生成環境；這些展示檔不是可編輯身體圖集。欲重建或套用身體仍需取得使用者指定的私人素材包。例外不擴及新人物的照片、聲音或成品。

從乾淨電腦驗證第四輪時，依序進行：

```powershell
# 只驗證展示檔，不下載模型：
python scripts/verify-demo.py
# 需要重新製片才安裝依賴並檢測當前機器：
.\scripts\setup.ps1 -PythonCommand python -RenderTools
.\.venv\Scripts\python.exe -m avatar_workflow doctor
# 取得私人素材包並比對旁附SHA256後：
.\.venv\Scripts\python.exe -m avatar_workflow unpack '私人素材包路徑\round04_asset_pack.zip'
node scripts/build-sample.cjs round04
$env:AVATAR_TEST_ROUND='round04'
npm.cmd test
node scripts/hf.cjs check samples/round04/mode2 --snapshots
```

先做一支13秒本機渲染，檢查音軌、字幕、嘴型與肩膀，記錄耗時與失敗原因，再換新人物。原`round04_asset_pack.zip`及speech欄位是生成時快照；本次驗收另存於示範manifest，不為更新驗收而改動原聲音或時間。只重建現有時間資料不用安裝ASR模型；新台詞重新配音才依第四輪文件安裝可選對齊依賴。模型推薦是候選選擇，本專案沒有把所有大型候選自動裝到另一台電腦。

阿忠測試素材可另外建立私人素材包：

```powershell
.\.venv\Scripts\python.exe -m avatar_workflow pack
```

產生 `outputs/round01_asset_pack.zip` 及 `.zip.sha256`，只包含允許清單中的兩張生成角色圖、定稿台詞、配音、嘴型與字幕資料；不包含原始海報、憑證、環境、硬體路徑或第三方工具。ZIP 本身含角色和聲音，應放使用者指定的私人 Drive 資料夾；目前命令只建立本機檔案，不上傳。

第二輪可用相同方式加上 `--round round02`，產生獨立 `outputs/round02_asset_pack.zip`；匯入依 manifest 輪次選擇允許清單，舊 round01 包仍可匯入。重建命令為 `node scripts/build-sample.cjs round02`；動畫測試先設 `$env:AVATAR_TEST_ROUND='round02'`，實際 MP4 驗證加上 `--round round02`。完整聲線與動作選項見 `兒童聲線選單與第二輪製作.md`。

另一台電腦的 Agent：

1. 取得 Git repo 程式版本，依開工順序讀文件。
2. 重建本機依賴與重新檢測硬體。
3. 從使用者指定的私人雲端取得素材包，另比對旁附 SHA256，再匯入：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '下載位置\round01_asset_pack.zip'
.\.venv\Scripts\python.exe -m avatar_workflow unpack '下載位置\round01_asset_pack.zip'
```

匯入時驗證清單、檔案大小與每檔雜湊，拒絕路徑跳脫、額外檔案、重複檔名及不同內容的覆寫。ZIP 內自帶雜湊只能檢查一致性，不能單獨證明寄件者可信；旁附 ZIP 雜湊須由可信來源取得。

4. 先重建阿忠三種模式，確認與原電腦相同，再依新硬體推薦做可選模型短測。新模型使用相同台詞、角色、時長、版位及解析度，記錄耗時、峰值 VRAM、角色一致性、中文嘴型、動作是否越界及授權。
5. 將實測摘要更新在 `專案進度.md`，詳細資料放 `docs/`；不要另建第二份交接文件。

## 重跑第一輪

匯入素材後可直接重建，不需重新呼叫配音服務：

```powershell
node scripts/build-sample.cjs
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
npm.cmd test
node scripts/hf.cjs check samples/round01/mode1 --snapshots
node scripts/hf.cjs preview samples/round01/mode1 --background --port 3017
```

若要新配音版本，指定新資料夾，避免覆寫已驗收音檔：

```powershell
.\.venv\Scripts\python.exe -m avatar_workflow speech --script outputs/round01/test_script.txt --voice zh-TW-YunJheNeural --output outputs/round01/audio_v2
.\.venv\Scripts\python.exe -m avatar_workflow lips --audio outputs/round01/audio_v2/voice.wav --output outputs/round01/audio_v2/mouths.json
```

目前 `build-sample.cjs` 固定讀 `audio/` 的本輪凍結素材；聲音驗收後，需調整讀取版本並重新產生字幕資料，不能只替換 WAV 而沿用舊嘴型／字幕。尚未提供任意新腳本的一鍵正式製片介面。

三種模式分別檢查後，測試 MP4 輸出命令如下（正式作品仍先讓使用者預覽與驗收）：

```powershell
node scripts/hf.cjs render samples/round01/mode1 --quality draft --fps 24 --workers 1 --no-browser-gpu --output outputs/round01/mode1_hands.mp4
node scripts/hf.cjs render samples/round01/mode2 --quality draft --fps 24 --workers 1 --no-browser-gpu --output outputs/round01/mode2_natural.mp4
node scripts/hf.cjs render samples/round01/mode3 --quality draft --fps 24 --workers 1 --no-browser-gpu --output outputs/round01/mode3_lively.mp4
```

`scripts/hf.cjs` 自動尋找本機 `.venv`、專案工具、獨立瀏覽器與工作目錄，沒有寫死本使用者家目錄。`AVATAR_CHROME` 可覆寫瀏覽器選擇；HyperFrames 的紀錄、快取和預覽狀態均放 `work/`。目前 PNG 的 SVG 剪裁分層只適用阿忠，不是自動人體骨架辨識。

## 來源與限制

- [Edge-TTS](https://github.com/rany2/edge-tts)：免費線上用戶端，會傳送台詞到線上服務；並非 Microsoft 正式商用 API，連線與條款需持續確認，不是離線開源語音模型。
- [Rhubarb Lip Sync](https://github.com/DanielSWolf/rhubarb-lip-sync)：CPU 音訊分析，中文使用 phonetic 近似嘴型；輸出的是嘴型時間，不會生成全身動作。本輪肢體由本專案 2D rig 控制。
- [FFmpeg 下載頁](https://ffmpeg.org/download.html)、[Gyan builds](https://www.gyan.dev/ffmpeg/builds/)：FFmpeg 官網提供原始碼並連至 Windows build 供應者。
- [Chrome for Testing](https://googlechromelabs.github.io/chrome-for-testing/)：獨立渲染瀏覽器來源。
- [Noto Sans TC](https://github.com/google/fonts/tree/main/ofl/notosanstc)：本機字型隨附 OFL，避免依賴另一台電腦是否安裝中文字型。
- 其他候選的授權、星數日期與官方連結見 `免費開源影音工具評估_2026-10-23.md`。星數會變動，不能拿舊快照當當日排名。

本輪 npm audit 未發現已知漏洞，但不等於惡意程式掃描。Windows Defender 指令回傳 `0x80004005`，掃描未完成；不能寫成「保證無惡意程式」。下載來源與雜湊、授權及實測紀錄必須分別列明。
