# 本機生圖與角色多視角資產研究

查證日期：2026-10-24（Asia/Taipei）。只引用官方模型卡、作者repo與官方文件。本次研究沒有安裝／下載大型模型、上傳私人照片、訓練LoRA或新增影片；候選不是已驗證能力。最新階段仍由專案進度統一記錄。

## 千問是哪個模型

「千問」是阿里巴巴Qwen系列。本任務應找Qwen-Image生圖／圖像編輯，不是Qwen3-TTS語音、Qwen-VL圖片理解或一般文字聊天模型；三者不能互相當作已安裝功能。

| 模型與官方來源 | 本專案可評估的用途 | 已核對授權／取捨 |
| --- | --- | --- |
| [Qwen-Image-Edit-2511](https://huggingface.co/Qwen/Qwen-Image-Edit-2511) | 以照片或已接受角色作參考，改畫風、人物一致性及多圖合成；優先作Q版頭像／指定身體的本機候選 | 模型卡Apache2.0；屬20B系列，完整管線不是低資源即用，未對阿德實測 |
| [Qwen-Image-2512](https://huggingface.co/Qwen/Qwen-Image-2512) | 文生圖、教學背景與一般角色設計 | Apache2.0；它是文生圖分支，不能直接當作Edit-2511同一API或同一LoRA底模 |
| [Qwen-Image-2.1](https://huggingface.co/Qwen/Qwen-Image-2.1)／[2.1-Turbo](https://huggingface.co/Qwen/Qwen-Image-2.1-Turbo) | 新版統一生成／編輯，可多參考圖與原生透明圖；Turbo為另行評估的加速分支 | 兩者模型卡皆qwen-research，不能沿用2511的Apache標籤。依用途另核對，不作本專案無限制公開重用的預設 |
| [Qwen-Image-Layered](https://huggingface.co/Qwen/Qwen-Image-Layered) | 將圖分解為多層RGBA，研究人物與背景或部件分離 | Apache2.0；語意圖層不是已帶肩髖重疊、肘膝連續材質的可動畫骨架，不能直接取代現有rig |
| [FLUX.2-klein-4B](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B) | 額外的較小生成／多參考編輯候選，與千問使用同一角色比較 | 此4B型號Apache2.0；官方模型卡寫約13GB VRAM，非「4B所以任意4GB顯卡可跑」。不把其他型號的授權／硬體套過來 |

推薦先以Edit-2511做「保留人物、轉Q版與參考編輯」，背景需求再評估2512；若新版2.1的用途與授權符合要求，再加入比較。不是所有情況都應選最新型號，也沒有依排行榜斷言哪個一定比使用者指定GPT Image 2.5好。這是本專案根據用途的選型建議，尚無同角色A/B生成結果。

[Qwen2.1原文授權](https://huggingface.co/Qwen/Qwen-Image-2.1/raw/main/LICENSE)把Non-Commercial定義為研究／評估，授權範圍限非商業用途；不能因「公開下載」就寫成所有教學／發布用途皆無限制。日後實際用途、修改及散布依該版本原文確認，模型本體不放入本repo。

官方[2.1 repo](https://github.com/QwenLM/Qwen-Image-2.1)列2026-09-20基礎版、2026-10-09 Turbo；基礎範例與8步Turbo是不同設定。需記實際checkpoint、revision、推論器及精度，不把加速版當作同品質保證。其「7B」指視覺生成Transformer，另有Qwen3-VL 8B文字／圖像編碼器與RGBA VAE；不能只用7B估整套記憶體。

GPT Image 2.5的官方名稱可由[OpenAI Sunburst文件](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst)核對，精細編輯可作優先選擇；但官方API型號存在不代表另一台Agent已有該工具或帳號權限。既有內建image_gen未暴露版本的素材仍記未暴露，不補寫虛構型號。

## 本機硬體判斷與保持品質

本次重新doctor：i5-7500／4執行緒、RAM15.92GiB／當時可用6.52GiB、GT710 2GB／當時可用1213MiB、驅動456.71、CUDA架構未知、可用磁碟193.07GiB。這是當下觀測，不是另一台電腦規格；doctor未探測SadTalker子環境的torch，不能用主環境torch_installed=false否認已成功CPU對嘴。

這台電腦已能以CPU慢速完成已接受SadTalker並合成1080p，尚無上述本機生圖相容或品質實測。研究結論是**不在GT710上預設安裝整套千問**；沿用已接受角色，或在較強電腦生成驗收後帶回合成，均可保持成品標準。

以下是本專案評估方向，不是官方最低規格，也不作自動安裝條件：

| 實際條件 | 可採取的做法 |
| --- | --- |
| 舊GPU、無適合CUDA或架構未知 | 用已接受靜態資產，CPU對嘴／合成；生圖安排到已授權可用的工具或較強電腦，不切回已拒絕SVG嘴型 |
| 現代GPU約8～12GiB，RAM充足 | 僅列卸載／量化的研究候選，先小樣；不足以承諾原精度整套模型或同品質，缺RAM仍可能失敗 |
| 現代GPU約16～24GiB，RAM32～64GiB以上及足夠磁碟 | 優先安排一個候選的實測；仍需編碼器卸載、有效精度、驅動／框架相容與實際峰值驗證 |
| 更高顯存 | 也需按完整checkpoint與解析度量測；不能單看容量，不能相加兩張顯卡就當作單卡可載入 |

20B的BF16權重僅按2bytes／參數粗估就約40GB，還未含編碼器、VAE與中間張量；這是記憶體算式，非供應商實測。官方[舊Qwen-Image repo](https://github.com/QwenLM/Qwen-Image)雖連到DiffSynth逐層offload的4GB案例，不能推成GT710 2GB可跑，或不需充足RAM／新驅動。[2.1模型卡](https://huggingface.co/Qwen/Qwen-Image-2.1#memory-optimization)也提供CPU offload，但沒有為本PC保證速度或最低VRAM。

品質保護順序：保留已接受原圖與最終規格→單工作／batch1→CPU卸載、切片與快取→量化／蒸餾／少步數另作同角色比較。後三者可能改變眼鏡、五官、文字與手腳，未驗收不得自動替換。不能把512px素材直接放大到1080p就聲稱品質沒下降。

接入可考慮本機ComfyUI工作流或隔離的Diffusers腳本；兩者是執行器，不是模型本體，也不代表所有節點離線免費。優先官方原生節點與固定版本，記錄workflow JSON／程式commit及每個權重來源；本次未安裝任一執行器。2.1的[官方repo](https://github.com/QwenLM/Qwen-Image-2.1)有ComfyUI與Diffusers入口，可作未來安裝依據。

## 多視角素材、角色設定圖與LoRA的差別

| 名稱 | 內容與用途 | 是否必須訓練 |
| --- | --- | --- |
| 角色設定圖／轉面圖（character sheet／turnaround） | 同一角色正面、左右45°、左右90°、背面，檢查服裝、比例及身份一致 | 否；圖片可以由參考編輯生成並逐張驗收 |
| 角色資產庫 | 大頭／半身／全身、表情、角度、透明圖、來源與驗收清單，各檔可獨立重用 | 否；不是只有一張拼在一起的展示圖 |
| 動畫分層圖集／sprite atlas | 頭、軀幹、含袖手臂、腿、鞋及必要重疊材質，配對骨架或網格校準 | 否；需要工程綁定與連續動作檢查 |
| 個人角色LoRA | 用經確認的資料訓練額外小權重，配指定底模生成此角色或畫風 | 是；不能只把多張圖排在一起便稱為LoRA |
| 3D角色／骨架 | 真正連續轉身、各方向姿勢與遮擋 | 不是多角度2D圖自動變成3D；屬另一套建模與動畫流程 |

依[Diffusers官方LoRA文件](https://huggingface.co/docs/diffusers/training/lora)，LoRA是額外可訓練權重的技術。圖片庫可成為訓練資料的一部分，但訓練出的權重仍依賴底模、版本及架構；Edit-2511、2512與2.1的adapter不能無驗證混用。社群「多角度LoRA」通常教角度控制，不等於已訓練使用者身份；2511提到整合LoRA能力也不代表讀一張照片就已有使用者專屬LoRA。

## 建議的角色資產順序

先建立使用者接受的正面主設計，固定辨識特徵／衣服／鞋／頭身比例。再以同一主設計及必要真人參考，依序做大頭、半身、全身，少量中性／微笑／說話表情，最後左右45°、左右90°與背面。先生成各自獨立高品質檔，再附一張總覽設定圖；不要將小格拼圖當作唯一高解析來源。

單張正面照片沒有真實背面資料；側面鼻形、髮型背部、背後衣服若未提供，只能是設計補完，需要使用者接受。不得將生成的新視角說成照片還原。身份一致不能只靠同seed，應比對臉型、髮線、眼鏡、衣服標記、鞋、身形與畫風；不合格變體不入庫。

資產建議命名為view_front／left45／right45／left90／right90／back，再分head／halfbody／fullbody與expression。私人清單記錄人物ID、參考來源SHA256、模型／revision／prompt／seed／精度、尺寸／alpha、是否觀測或補完、父資產、接受範圍與相容rig；未公開授權的參考圖、LoRA及整套圖庫不進Git／Pages。這是未來資料格式設計，未宣稱當前packer已支援全部欄位。

大量不同情境生圖時若參考編輯仍常身份漂移，再考慮LoRA。先用少量已驗收參考測編輯效果，若已穩定就不額外訓練。訓練資料須人工篩選與標註，保留獨立驗證視角，不以未審核生成圖大量回灌；資料數量、rank、步數與資源需求依選定訓練器實測，不捏造固定張數即必成功。

## 對嘴與視角的邊界

目前已接受的是阿德正面及小角度頭傾、三種原地動作；多視角靜態圖不等於SadTalker已能在90°、背面或連續轉身穩定對嘴。背面沒有可見嘴巴，敘事可保留配音而不繪不存在的嘴。要人物邊轉到側／背面邊說話，需另做姿勢轉換或3D／其他模型的短測與驗收，不能把多張臉切換當作已完成自然轉身。

## 研究踩坑與回復方式

- 現象／基準：已接受13秒本人身體，尚缺通用本機生圖與多視角。候選模型名稱容易把語音、圖片理解及生圖混淆。
- 實際核實：2.1／Turbo可下載但授權不同；「7B」未含全部管線；Layered不是自動動畫rig；小顯存offload案例不是GT710相容證據。
- 方法：查讀上述官方模型卡、license與repo；重新doctor。沒有以非官方排行榜、量化版下載量或示範圖取代本角色實測。
- 驗證證據：官方連結與日期如上；私人doctor為work/hardware/report.json。候選installed／runtime_verified／character_quality_verified均不得寫true。
- 耗時：本次只有研究與文件整理，未精確計時；模型下載、生成、峰值RAM／VRAM及LoRA訓練耗時均未量測。
- 採用／放棄：採用參考編輯＋經驗收角色資產庫為第一階段設計；LoRA後置，2.1列受限選用；沒有刪除其他候選或宣稱其不可用。
- 限制／回復：已接受round11及較早基準全部保留；模型失敗不動原圖、原音與原片。需要換底模、量化或風格時另存實驗輪次，重新驗收，不能覆寫已接受素材。
