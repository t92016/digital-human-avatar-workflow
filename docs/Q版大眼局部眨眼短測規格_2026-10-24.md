# Q版大眼：局部眨眼短測規格

本文件前半保存測試設計，後半記錄第八輪實作與踩坑；跨 Agent 的驗收狀態與下一步仍集中於 `專案進度.md`。使用者接受第七輪穩定效果，要求下一階段明顯、自然的閉眼與張眼；若仍不自然，先按回饋修正，之後才考慮以對嘴為主。

## 可行性判斷

值得繼續做短測，但不沿用提高SadTalker blink ratio的方案。前輪五組單格探測已顯示高增益影響嘴角、臉型及姿態；這不是只改眼皮的控制器。詳見 [前輪踩坑及優化紀錄](SadTalker跳動與眨眼踩坑及優化紀錄_2026-10-24.md)。不能把原生隨機開關或某張半閉眼圖當成自然完整眨眼已完成。

下一輪保留已接受的SadTalker嘴型與穩定片，另製作「同角色局部眼皮層」。這是額外的眨眼合成策略，不宣稱SadTalker模型本身已能讓此Q版大眼自然完全閉合。

## 固定輸入與素材製作

- 基準：`outputs/round07/head_stabilized.mp4`，SHA256 `de3f5881ac890d10a7fab4feb75ef7675ee2677a777a33d0d20658179b243b9d`，4.4秒／25fps／1254×1254。此版跳動改善已被接受。
- 聲音：沿用既有家豪1602短音訊，不做TTS網站轉換，也不等本機TTS安裝後才測眨眼。原完整WAV仍在 `outputs/round05/audio/ttsmaker_original.wav`，短音訊在 `outputs/round06/sadtalker-head-v2/jiahao-sample.wav`。
- 頭像、眼鏡、畫風、比例及用途沿用已確認設定；只處理眼皮，不重畫制服、身體或嘴型，不再重問相同風格與聲線。
- 建議從穩定片擷取一張合適的開眼畫格作編輯目標，先用view_image檢視，再以內建image_gen生成半閉眼、閉眼關鍵圖。以影片畫格為目標可減少原始銳利PNG與256版影片柔化質感的落差。
- 明確鎖定短髮、成人臉型、眼鏡形狀／位置、眉毛、鼻子、嘴巴、頭部角度與構圖。只在雙眼眼皮區域取用合格素材；模型若連帶改嘴或臉，不得整張頭像取代已驗收片。
- 生圖使用實際可用的內建工具，提示、來源角色、輸出與可取得的模型資訊都記錄；工具未暴露精確版本時不宣稱已鎖定GPT Image 2.5。

## 動作與驗收

先看開眼／半閉眼／閉眼三張靜態圖，確認可用才做一次開→半閉→全閉→半開→全開。以25fps下約6～10幀（0.24～0.40秒）作為創作起點，不是生理標準；在既有4.4秒片內放一次明顯眨眼即可。不要為了試眼皮先重跑整段昂貴的SadTalker。

眼部局部遮罩、柔邊及必要追蹤要逐角色校準。不能只把整張眼睛區塊壓扁，也不能只用兩張開／閉眼圖直接溶解，造成瞳孔重影。嘴巴和下顎交由原片，保留幀數／幀序／音訊時間；在真正長片中再以全片時鐘安排不等間隔。

驗收重點：閉合峰值雙眼明顯閉起、虹膜不殘留，眼鏡與眉毛不跟著變形；過渡無閃邊或重影；張開後回到原眼型；嘴唇、下顎及配音同步維持。正常速度與0.5倍速都要看，擷取完整開閉過程，不只看峰值圖。

新片另存 `outputs/round08/` 或新的版本目錄，素材／中間檔放 `work/round08/`，保留第七輪原片。驗證實際MP4解碼、音軌、幀數、字幕未被誤套及局部合成邊界，將方法／參數／耗時／失敗圖與結果補進對應踩坑紀錄。新眨眼仍須使用者驗收，不能沿用第七輪穩定效果的接受狀態。

如果不自然，依使用者回饋調整眼型／過渡／速度；仍不合適時，由使用者決定使用已接受的對嘴與穩定片，不將高增益改臉探測當作替代成品。以上是前一階段的設計；以下才是本次實際產出。

### 素材、方法與版本

1. 取第七輪第42幀（1.68秒）的實際開眼畫格，保存 `work/round08/baseline_f042.png`，先以 view_image 檢視。
2. 以內建 `image_gen.imagegen` 分兩次編輯同一畫格，生成半閉眼與全閉眼參考，各1254×1254，黑背景沿用。提示要求保留成人臉型、髮型、眼鏡、眉毛、鼻、嘴、下顎、構圖與柔化質感。工具沒有暴露精確後端型號，不宣稱鎖定 GPT Image 2.5。原生輸出複製到 `work/round08/eyes_half_generated_v1.png`、`eyes_closed_generated_v1.png`，沒有用生成的整張臉取代基準片。
3. 開／半閉／全閉三張先檢視後才渲染連續片。半閉圖供人工校準眼皮曲線；實際瞳孔與眼白取自每一幀原片，沒有複製生成圖的虹膜。全閉圖只提供皮膚與閉眼線材質。
4. 新增 `scripts/compose-local-blink.py` 與 `config/ade-blink-round08.json`。每眼以11個橫向控制點定義原上眼皮、半閉、閉合線與下眼皮；上眼皮材質依曲線重映射並遮住原虹膜，下眼皮小幅上合。不壓扁整塊眼睛，不以兩張眼睛直接溶解，沒有跨幀混合嘴型。
5. 局部 ECC 平移追蹤採鏡框周邊 ROI，排除眼球區，最多60次迭代、epsilon1e-5、Gaussian5；相關低於0.85或平移超5px即停止。這次14筆估計的最小相關0.889715、最大水平0.574916px／垂直1.961671px；僅用於七張非開眼畫格的眼皮位置，不重新穩定全頭或教材。
6. 25fps，第43～51幀（1.72～2.04秒）安排一次完整開閉，閉合量 `[0,0.22,0.64,1,1,0.82,0.48,0.18,0]`；第46、47幀（1.84、1.88秒）全閉，峰值共0.08秒。由開眼端點到重新張眼0.32秒，這是本角色的創作參數，不是通用生理標準。
7. OpenCV4.8.1／NumPy1.23.5／Pillow9.5.0，沿用獨立 Python3.10.21；FFmpeg9.0.2、H.264 CRF12／fast／2threads／yuv420p，AAC直接複製。眼部遮罩是有限範圍，柔邊外像素明確維持原值。

準備提示在 `work/round08/closed-eye-prompt.txt`、`half-eye-prompt.txt`；**實際送入工具的完整提示**、輸出原檔名、素材SHA256與耗時在 [本機素材來源紀錄](../work/round08/image-generation-provenance.json)。素材與原生輸出都是私人，不擴大 GitHub 展示例外。

### 遇到的缺陷、原因與修正

首版靜態過渡在新眼皮上方殘留原開眼上眼線，形成淡淡雙弧。實際原因是遮罩柔邊從原上眼皮曲線上方18px開始，尚未完全變成不透明時便碰到原眼線；不是高眨眼增益不足，也不是必須重畫整張臉。

將上方起點改為曲線上方28px，10px柔邊在原眼線之前結束，工作框上界一併擴至32px；重新檢視關鍵圖確認淡弧已消除，才輸出影片。失敗靜態圖保留於 `work/round08/rejected-keyframes-v1/`，沒有把它當成合格連續眨眼。這一修正只擴到鏡框內的眼皮皮膚，不延伸到眉毛、鼻、嘴或臉部輪廓。

### 採用範圍、限制與回復

生成時此候選的manifest為 `user_accepted=false`；使用者於2026-10-24後續明確表示「剛剛我覺得眨眼的自然度可以接受」，現已更新manifest為true，影片與音訊不重製。接受範圍僅這位阿德、一次完整眨眼、既有4.4秒頭像及家豪音訊；尚未驗證任意人物眼鏡／大眼、長片不定時眨眼、去背及身體接回。固定控制點與鏡框ROI需逐角色校準，不是通用自動眨眼模型。原technical-verification及播放器待驗收字樣保留為生成時快照，後續驗收以manifest及專案進度為準。
